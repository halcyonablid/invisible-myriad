# 新增笔记：先确定关系，再让地址带着内容生长

上一篇讲了地址怎样形成 Mermaid 图。这一篇回到日常写作：打开一篇已有笔记，怎样在它附近继续写？新笔记应当与它同层，还是进入它的下一层？写完之后，又怎样从两侧视图找到它？

这里配合使用三个插件：**相似笔记 · Similar Note** 负责创建，**EVA 分支树**帮助看分支，**ATOM 侧栏导航**帮助看排列和定位。

## A．先看懂地址：同层补充和向下展开有什么不同？

### 文件名中，地址和标题各做一件事

```text
ATOM@002.002.002- 其次是新增笔记.md
      地址          标题
```

`ATOM@` 标识这类编号笔记；后面的地址说明它处在什么位置；`- ` 后是人能读懂的标题。**半角短横线后要有一个空格**，这样相关视图才能按预期拆出地址与标题。

地址不是重要性评分，也不是日期。把它当作一个可以不断扩展的位置：新内容在哪里接入，取决于它与已有内容的关系。

### 点号 `.`：进入下一层

```text
002                    组件使用说明
└─ 002.002             具体插件的应用、说明和例子
   ├─ 002.002.001      Mermaid 图的使用方法
   ├─ 002.002.002      新增笔记与地址规则
   │  └─ 002.002.002.001  一次新增笔记的练习
   └─ 002.002.003      树和关键词的结合
```

前三篇说明是同层的兄弟笔记。“一次新增笔记的练习”则进入第二篇内部，成为它的子级。**在完整地址后添加 `.编号`，才是这里说的向下递进一层。**

### 字母 `A`、`B`：在同一层插入和延展

如果 `002.002.002` 后面已经有了 `002.002.003`，此时又想在第二篇附近补一条内容，不必把后面的笔记全部改号，可以使用：

```text
002.002.002       新增笔记与地址规则
002.002.002A      关于编号的一点补充
002.002.002B      另一点补充
002.002.003       树和关键词的结合
```

这几条仍然属于 `002.002` 这一层。`002A` 是同一个地址段的延展，不是 `002` 下面的下一层；即使继续延展成 `002A001`，只要没有新增点号，也没有因此增加点号层级。

对比这三种关系：

| 地址写法 | 这里表达的意思 |
| --- | --- |
| `002.002.002A` | 在当前层附近补充一条，父级仍是 `002.002` |
| `002.002.002.001` | 进入 `002.002.002` 内部展开 |
| `002.002.002+001` | 从该节点发展到一个新状态，用于上一篇的 Mermaid 状态关系 |

字母后缀、点号与加号不能互换。这里的字母是 ATOM 地址的一部分，也不要和关键词义名开头的分组字母混为一谈。

## B．用“相似笔记”插件创建

### 最常用的四步

1. 在主编辑区打开作为出发点的 Markdown 笔记，先确认它的地址。
2. 点击左侧工具栏的“创建相似笔记”图标；也可以按 `Ctrl+P` 搜索 **创建相似笔记**，或在文件列表里右键该笔记选择同名操作。
3. 选择 **智能编号** 或 **子级编号**，填写标题，并检查弹窗里的完整路径预览。
4. 点击 **创建并打开**。新笔记打开后，再写它自己的正文。

此插件已经独立运行，不需要再通过 Templater 执行模板。想用键盘快速新增，可以在 Obsidian 的快捷键设置中给“创建相似笔记”绑定自己顺手的组合键。

### 两个编号按钮怎样选择？

| 你的意图 | 选择 | 例子与条件 |
| --- | --- | --- |
| 在当前层继续补充 | 智能编号 | 从 `002.002.002` 出发，若 `002.002.003` 空闲，就使用它 |
| 下一个编号已占用，仍想留在当前层 | 智能编号 | 若 `.003` 已占用，会尝试从源号延展为 `002.002.002A`；若也占用，再继续尝试延展 |
| 当前地址以大写字母结尾 | 智能编号 | `002.002.002A` 可递增为 `002.002.002B`，以预览和占用情况为准 |
| 把当前内容展开得更细 | 子级编号 | 从 `002.002.002.001` 开始找空闲子号，已占用则尝试 `.002`、`.003` 等 |

插件会检查全库 Markdown 文件的编号，而不只是当前文件夹。**最终以弹窗预览为准**：它负责计算可用地址，你负责判断这个地址是否符合内容关系。

“智能编号”不会替你判断文章在概念上属于哪里，也不会自动选择 Mermaid 的 `+` 状态发展。当前两个模式只提供上述递增、延展与子级编号；不要把“智能”理解成自动整理全库。

### 新笔记带走什么，留下什么？

“相似”主要指编号与必要属性的延续，并不复制整篇文章。

- 新生成创建日期、创建时间，以及 `atomle: true`、`antinet: atom`、`树的结构: true`。
- 源笔记有 `所属块` 时继承它，方便继续从新笔记打开同一张 Mermaid 图；源笔记没有时，不会凭空猜一个。
- 新地址含点号时，按最后一个点之前的编号寻找父笔记，找到后写入 `上级条目` 链接。编号对应多个父笔记时会拒绝创建；找不到父笔记时，不会编造链接。
- 继承正文中独占一行的 `字段:: 值`。因此建完后仍要看一眼这些字段是否适合新内容。
- 不复制正文，不照搬全部 YAML 属性，也不会自动复制 `mermaid图之起始` 标记；不生成螃蟹复习属性。

`上级条目` 和 `所属块` 也不同：前者指向编号上的父笔记，后者指向打开 Mermaid 图的入口。它们可以不同，不需要为了“看起来一致”改成同一篇。

新文件默认跟随 Obsidian 的新笔记存放位置。需要时，可以在本插件设置中改成源笔记所在文件夹，或一个已存在的库内文件夹。**磁盘文件夹决定文件存在哪里，ATOM 地址决定这些视图怎样组织它。**

### 暂时不创建时

“稍后再建”、Esc 或普通关闭会保留名称和编号方式的草稿；明确不需要时用“放弃草稿”。如果提示草稿保存失败，先保留输入文字。

如果提交时提示编号或源内容变化，重新看预览再确认。如果显示“已创建，但打开失败”，使用“打开已创建笔记”重试打开即可，不必重新创建一份。

## C．两侧视图怎样配合？

| 视图 | 适合回答的问题 | 命令面板中的入口 |
| --- | --- | --- |
| 左侧 EVA 分支树 | 我现在在哪个分支？上面是什么、旁边有什么、哪些部分可以展开？ | **打开/收起左侧分支树并定位当前笔记** |
| 右侧 ATOM 侧栏导航 | 这篇在编号列表的什么位置？相邻条目如何排列？ | **打开右侧 ATOM 导航并定位当前笔记** |

先在主编辑区打开一篇笔记，再调用对应命令。视图中的“定位”按钮也可用于重新找到当前笔记。

### EVA 分支树：看上下文和分支形状

树上的 `│`、`├─` 和折叠三角帮助阅读层级。它主要围绕当前笔记的主分支显示，并可能根据索引规则隐藏 Mermaid 内部节点，只突出所属图的入口。所以，左边看到的不是任何时候都展开的全库清单。

绿色提示用于识别 Mermaid 起点，当前笔记或所属图还有专门的定位提示。某条不在可见列表时，先检查折叠、深度与隐藏规则，不要据此认为笔记消失了。

### ATOM 侧栏导航：看排序和颜色分组

右侧列表按名称与编号顺序组织符合条件的 ATOM 笔记。当前规则要求文件名以 `ATOM@` 开头、符合 `ATOM@地址- 标题` 格式，并且属性 `antinet` 为 `atom`；插件依赖 Dataview 读取这些信息。

背景颜色帮助辨认地址结构分组。在常用的点号编号中，`001`、`001A`、`001A001` 这类同段延展按同类格式处理；新增点号层级则改变结构格式。另有“索引关键词已录入”的专门颜色标记。

因此，**颜色用于辅助阅读，准确关系仍看地址与层级线**。同色不一定同父级，也不是某个固定颜色永远代表第几层。

### 新建之后没有马上显示怎么办？

先确认新文件已经打开或能在文件列表中找到，再给索引一点更新时间，使用侧栏的定位或刷新。右侧主要依赖 Dataview，左侧依赖 EVA 索引，两边不一定在同一时刻更新。

检查文件名中的 `- `、`antinet: atom`、当前分支及折叠范围，通常比再次创建一篇更有用。

## 做一次小练习

找一篇适合补充的笔记，先决定“同层补充”还是“内部展开”，用对应模式创建，读一遍预览地址，再到两侧视图定位。接着写下新笔记自己的问题和内容。
