# Keyword BUS Pattern

## 1. 作用域

这套协议只服务：

1. 单个 Tab 下的普通条目
2. 这些条目的关键词组织、展示、定位
3. 基于 BUS 的顺延新增

它不服务：

1. 范式条目
2. 范式关键词
3. 跨 Tab 全局关键词

## 2. 正交原则

1. Tab 普通条目关键词与范式关键词完全隔离
2. 单 Tab 作用域优先，不默认跨 Tab 聚合
3. 先复用现有 reveal / pending focus / render 后定位链路，不另造手写 DOM 协议

## 3. 最小模型

### 关键词定义

至少要能表达：

1. 稳定 id
2. `label`
3. `pathLabel`
4. 层级路径
5. 所属 tab

### 条目绑定

至少要能表达：

1. 条目稳定 id
2. 关键词稳定 id
3. 所属 tab

### 抽屉状态

单独用扁平字典保存，key 必须是稳定 id，不要直接拿 `label` 或原始 `+` 文本当 key。

## 4. UI 合同

视觉语言严格贴近既有“关键词索引管理系统”的胶囊/抽屉方式：

1. 顶层先显示关键词胶囊
2. 有子级的节点渲染为父级胶囊容器
3. 展开后显示子胶囊和条目叶子
4. 条目叶子点击后滚动到真实条目
5. `BUS+1` 是独立动作，不与展开动作混在同一控件

顶层默认左键语义应是“展开抽屉”，不是直接定位。

## 5. BUS 合同

### 命名

BUS 节点格式固定：

1. `BUS001.名称`
2. 以 `BUS` 开头
3. 编号固定宽度

### 作用域

BUS 递增不是针对某个 BUS 节点，而是针对当前关键词前缀作用域。

例如：

1. `项目推进+准备阶段+BUS001.需求澄清`
2. `项目推进+准备阶段+BUS002.风险整理`

则 `项目推进+准备阶段` 是 BUS 作用域。

### 顺延产物

点击 `BUS+1` 后，至少完成：

1. 在当前作用域下计算下一个编号
2. 生成新的 BUS 关键词路径
3. 新增一个普通 Tab 条目
4. 自动把该条目绑定到新关键词路径

不要只建关键词不建条目，也不要只建条目不补关键词。

## 6. 兼容原则

1. 旧平面关键词自动视为顶层节点
2. 新旧并行期统一走关键词树显示层
3. 升级后旧条目关键词不能丢
4. 重新渲染、切 capsule、切 tab 不能让历史关键词“看不见”

## 7. 嵌套 Tab 的注意项

如果父 Tab 会渲染子 Tab 条目：

1. 关键词归属仍应以条目真实所属 tab 为准
2. 父视图是否聚合显示子 tab 关键词，必须是显式设计，不要隐式混并
3. 定位时要能回到条目真实所在 tab / section

## 8. 禁止事项

1. 复用范式标签树偷做普通条目关键词树
2. 把关键词抽屉状态塞进范式 TOC 状态桶
3. 用插件私有 DOM 结构驱动 BUS 逻辑
4. 让新 UI 只支持新数据，不兼容旧数据
