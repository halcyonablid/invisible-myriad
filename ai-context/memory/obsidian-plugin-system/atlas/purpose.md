# Atlas Purpose

status: active
created: 2026-06-24

## Why This Atlas Exists

This Atlas is the maintained synthesis layer for the user's Obsidian plugin system.

It exists because the system has grown beyond isolated plugin facts. The user, Codex, MemPalace, Project Overview, Mandala, Keyword Index, EVA relations, Workspace Mount, Collection Card, GTD, Timeline, notes, and Mermaid graphs all participate in one operating environment.

The Atlas should reduce three kinds of friction:

1. Re-explaining tacit system knowledge in every conversation.
2. Re-deriving system understanding from raw plugin JSON, old cards, and source code each time.
3. Letting specialized terms drift through loose paraphrase.

## Long-Term Questions

The Atlas should help answer:

- What are the stable layers and ownership boundaries of the Obsidian plugin system?
- How should AI coaching read a project without flattening plugin column semantics?
- How do Antinet / ATOM / Mermaid addresses become upper-level symbolic structure?
- Which plugin owns which content, and which plugin only projects or exports it?
- What is confirmed by user practice, memory cards, code, or inference?
- What remains unknown and needs calibration?

## Boundaries

The Atlas is not a runtime plugin and does not own business data.

It does not replace:

- raw sources under `memory/obsidian-plugin-system/sources/`;
- reusable experience cards under `memory/obsidian-plugin-system/cards/`;
- engineering change records under `memory/obsidian-plugin-system/change-records/`;
- workflow hard rules under `prompts/rules/`;
- executable skill instructions under `skills/`.

The Atlas is a maintained, link-rich synthesis layer. Raw sources remain raw. Experience cards remain evidence. Change records remain factual engineering ledgers.
